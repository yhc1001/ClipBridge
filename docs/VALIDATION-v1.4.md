# v1.4.0 검증 결과 — 2026-10-21

v1.4.0은 시스템 Deskflow 설치를 사용하지 않고 앱 안의 입력 엔진을 실행합니다. **설치 독립성 검사와 실물 컴퓨터 사이의 입력 검사는 구분합니다.**

| 환경 | 자동 검사 | 배포본 검사 |
|---|---|---|
| Windows Server 2022 x64 CI | 87 통과, 다른 OS 모듈 2 제외 | EXE의 새/이전 설정 시작·정상 종료, 내장 core 실행·의존성·프로필 정리 통과 |
| macOS 15 Apple 칩 | 81 통과, 다른 OS 모듈 3 제외 | .app 시작·정상 종료, 내장 core 실행·의존성·프로필 정리 통과 |
| macOS 15 Intel | 81 통과, 다른 OS 모듈 3 제외 | 위와 동일 |
| Ubuntu 24.04 X11 x86_64 | 83 통과, 다른 OS 모듈 3 제외 | 패키지 시작·정상 종료, 내장 core 실행·의존성·프로필 정리, 두 가상 화면 입력 전송 통과 |

[Windows 빌드·검사](https://github.com/yhc1001/ClipBridge/actions/runs/39544711517) · [Mac 두 종류 빌드·검사](https://github.com/yhc1001/ClipBridge/actions/runs/39544714537) · [Linux 빌드·검사](https://github.com/yhc1001/ClipBridge/actions/runs/39544717390)

Windows CI에는 Deskflow가 설치되지 않았음을 먼저 확인했습니다. 배포본 검사에서도 시스템 설치 경로를 사용할 수 없게 하고, 실제 앱이 포함된 core를 골라 `--version`으로 실행하는지 확인합니다. native desktop 플러그인·DLL/프레임워크 로드와 소유자 전용 TLS 프로필 생성·삭제를 검사하며, 이 검사에서는 입력 후크를 켜지 않습니다.

Linux에서는 사용자 화면과 분리된 Xvfb 두 개에서 내장 엔진의 **실제 TLS 상호 인증, 서버 오른쪽 가장자리에서 클라이언트로 마우스 이동, 클라이언트 창의 키 수신**이 통과했습니다. 포인터는 XTest 장치 입력을 사용합니다. 이 검사는 한 CI 호스트의 두 가상 X11 데스크톱이며 실물·서로 다른 OS의 입력 결과는 아닙니다.

기존 Deskflow 인증서를 가져온 후 원본을 삭제해도 보호된 ClipBridge 설정으로 인증서를 복구하는 검사를 추가했습니다. 원본 인증서를 이미 잃은 예전 설정은 마우스만 비활성화하고 클립보드는 시작합니다. 원본 Deskflow 설정·실행·자동 시작은 변경하지 않았습니다.

배포 앱에서 Deskflow 설정 가져오기 버튼과 자동 프로필 탐색을 제거했습니다. 일회성 변환은 소스의 개발 도구에만 남기고, 일반 설정은 ClipBridge 연결 코드·화면 배치만 사용합니다. 이미 저장한 ClipBridge 설정은 보존합니다.

선택적인 Windows 마우스 방화벽 도구는 명령을 대체한 검사로 사설 프로필·지정 상대 IP·지정 TCP 포트 제한, 기존 클립보드 규칙 호환성, 공인 IP 거부를 확인했습니다. 실제 방화벽 규칙은 변경하지 않았으며 관리자 권한의 실제 등록은 미검증입니다.

## 클립보드 요청 항목

| 요청 항목 | 자동 검사의 범위 / 실물 앱 상태 |
|---|---|
| Main → newserver 텍스트 | 실제 TLS 소켓·Windows 네이티브 복사/등록 통과. 별도 PC 앱 붙여넣기 미검증 |
| newserver → Main 텍스트 | 양방향 처리 통과. 별도 PC 앱 붙여넣기 미검증 |
| PicPick 캡처 | PNG/DIB/DIBV5 변환·등록 통과. PicPick UI 미검증 |
| Windows 캡처 도구 | 이미지 변환·등록 통과. 캡처 도구 UI 미검증 |
| 브라우저 이미지 | PNG/Bitmap 처리 통과. 브라우저 UI 미검증 |
| Word/브라우저 HTML | HTML/RTF 처리·등록 통과. 해당 앱 UI 미검증 |
| Excel 표 | 텍스트·HTML·지원 공개 형식 통과. Excel UI·OLE/수식 유지 미검증 또는 지원 범위 밖 |
| 탐색기 파일 | 실제 파일 바이트·CF_HDROP 등록·해시 검사 통과. 탐색기 붙여넣기 UI 미검증 |
| 여러 파일 | 복수 루트·빈 폴더·4개 엔진 중계 통과 |
| 연결 끊김·재접속 | 자동 접속·기존 클립보드 미전송 통과. 이번 배포본으로 실제 PC 재접속 미검증 |
| 동시 복사 | 4개 엔진의 논리 순서 충돌 수렴 통과 |
| 중복 루프 | 네이티브·다중 엔진 중계의 중복 억제 통과 |
| 자동 시작 | 등록·해제·설정 보존 통과. 실제 재로그인 미검증 |
| Moonlight의 Ctrl+V | 서버 클립보드 등록까지 구현. Moonlight UI 미검증 |

다중 연결 검사는 한 호스트 안의 허브+참여 3개 엔진에서 실제 TLS·실제 파일 바이트와 메모리 클립보드 어댑터를 사용합니다. OS 클립보드는 각 OS의 별도 네이티브 검사입니다. 이 결과를 실물 Windows↔Mac↔Linux의 앱별 붙여넣기 검사로 해석하지 않습니다.

## 남은 실물 확인

- 서로 다른 실물 OS 사이의 마우스·키보드, 모니터/DPI/언어별 키 매핑과 macOS 권한 승인
- PicPick·캡처 도구·Explorer·Finder·GNOME/KDE·Word·Excel·브라우저·Moonlight UI
- 로그인 자동 시작의 실제 로그아웃/로그인, macOS 첫 실행/Gatekeeper
- 512MiB 클립보드·1TiB 파일·20,000개 항목·16대 최대 부하와 Ubuntu 24.04 이외 Linux

Linux Wayland 입력 엔진은 배포하지 않으며 백그라운드 클립보드 동작도 보장하지 않습니다. Windows UAC·잠금 화면·로그인 전 입력은 지원 범위가 아닙니다.
