# 여러 대 연결

## 구성

newserver 한 대를 허브로 지정하고 Main, Mac, 다른 Windows PC가 각각 허브에 연결합니다. 참여 컴퓨터끼리 직접 연결할 필요는 없습니다. 허브도 클립보드를 공유하므로 Moonlight 화면에서 newserver의 Ctrl+V를 그대로 사용합니다. 허브 1대 + 참여 컴퓨터 최대 16대를 등록할 수 있습니다. 실제 자동 검사의 동시 연결 규모는 총 4대입니다.

허브는 참여 컴퓨터마다 별도 TLS 연결을 유지합니다. 참여 컴퓨터에서 받은 항목을 허브 클립보드에 적용한 뒤 다른 연결로 전달하며 원래 보낸 컴퓨터에는 돌려보내지 않습니다. 텍스트, 이미지, HTML/RTF 및 실제 파일·폴더 데이터에 같은 전달 방식을 사용합니다. 각 컴퓨터의 형식별 켜기/끄기와 용량 제한은 계속 적용합니다.

연결된 모든 기기는 같은 클립보드 그룹입니다. 기기별 공유 그룹 분리, 허브 이중화, 허브끼리 연결하는 기능은 없습니다. 16대 제한을 채우면 사용하지 않는 장치 등록을 해제해야 새 장치를 추가할 수 있습니다.

## 연결과 승인

허브에서는 IP 입력이 필요 없습니다. 참여 컴퓨터는 허브의 LAN/Tailscale IP와 같은 포트를 설정합니다. 기본 포트는 TCP 45832입니다. 공인 IP는 허용하지 않습니다. IPv6는 허브의 고급 수신 IP도 해당 주소나 `::`로 설정해야 합니다. 허브의 Windows 방화벽 규칙은 사설 프로필·해당 프로그램·해당 TCP 포트에만 허용하고, 참여 컴퓨터의 IP 목록으로 제한할 수 있습니다.

관리자 PowerShell에서 선택적으로 다음과 같이 등록합니다. 새 컴퓨터를 추가할 때는 전체 허용 목록을 지정하여 다시 실행합니다. 이 스크립트는 기존 ClipBridge 전용 규칙을 교체합니다. 프로그램이 자동으로 방화벽을 바꾸지는 않습니다.

```powershell
.\Configure-Firewall.ps1 -PeerIp '192.168.0.10','192.168.0.11' -ExePath 'C:\Apps\ClipBridge\ClipBridge.exe'
```

연결 코드는 **승인 1회용**입니다. 최초 승인을 마치면 그 기기의 인증키를 따로 저장하고 다음 초대키를 새로 만듭니다. 같은 코드를 여러 기기에 미리 배포하지 마세요. 승인하지 않은 요청은 등록하지 않습니다. 승인한 기기는 재접속 때 승인을 다시 요청하지 않습니다. 각 기기는 허브 인증서의 SHA-256 지문도 검사합니다. 등록한 컴퓨터의 이름은 식별용이며 인증은 장치 UUID와 비밀키로 수행합니다.

허브의 장치 목록에서 특정 기기를 해제하면 해당 기기의 기존 키로 다시 접속할 수 없습니다. 해제 시 현재 연결들을 끊고 남은 기기들은 자동으로 재접속합니다. 다시 등록하려면 새 코드와 허브 승인이 필요합니다. 전체 초기화는 모든 승인과 초대키를 폐기합니다. 기기별 인증키와 초대키는 Windows DPAPI / Mac 키체인 기반 암호화로 보호합니다. 연결 코드는 비밀키를 포함하므로 신뢰할 수 있는 방법으로만 전달하세요.

## 파일과 충돌

파일은 먼저 허브가 수신하고, 다른 참여 컴퓨터에 각각 전송합니다. **v1.2.1부터 승인한 컴퓨터끼리는 파일도 확인 창 없이 자동 수신합니다.** 파일 켜기/끄기·차단·용량 제한은 각 기기에 적용합니다. 필요할 때만 고급 설정의 파일 수신 방식을 ‘전송마다 확인’으로 바꿀 수 있습니다. 이 선택은 재시작 후에도 유지합니다. 수동 확인 모드에서 한 기기가 거부하거나 승인을 미뤄도 다른 기기의 수신과 새 텍스트 복사는 진행됩니다.

v1.3.0 기본 파일 합계 제한은 전송당 16 GiB, 최대 1 TiB이며 항목 수는 20,000개입니다. 파일과 큰 클립보드는 256 KiB 단위로 전송합니다. 큰 클립보드에는 모든 기기를 v1.3.0으로 업데이트하세요. 허브에는 수신과 재전송에 필요한 임시 공간이 필요합니다. 경로 이동·예약 이름·심볼릭 링크·정션·UNC 경로는 차단합니다. 이동/잘라내기는 복사로 처리합니다. SHA-256으로 파일 내용을 확인하고 중단된 전송을 정리합니다.

붙여넣기를 위해 마지막 수신 파일을 임시 폴더에 유지합니다. 다음 파일 항목을 적용하거나 종료하면 정리하며, 다른 기기로 읽는 동안에는 삭제를 미룹니다. 종료하면 클립보드의 임시 파일 경로도 사용할 수 없으므로 붙여넣기를 먼저 완료하세요. 텍스트·이미지 기록은 디스크에 저장하지 않습니다.

동시에 복사하면 논리 순서 번호가 큰 항목을 선택하고 같은 번호는 장치 UUID로 결정합니다. PC 시계의 오차에는 영향을 받지 않습니다. 새 복사는 오래된 전송을 취소합니다. 출처 표시·순서 번호·SHA-256 중복 필터로 반복 동기화를 막습니다. 허브의 형식별 끄기·일시 중지는 해당 전달에도 적용됩니다. 허브 → 참여 컴퓨터 단방향은 허브에서 복사한 내용만 전달하는 모드입니다.

재연결은 최대 15초 간격으로 계속 시도합니다. 연결이 돌아왔을 때 기존 내용이나 연결이 끊긴 동안 복사한 내용을 재전송하지 않습니다. 허브를 끄면 참여 컴퓨터 사이의 공유도 중단됩니다. 로그인 전·잠금 화면·Windows 서비스 모드의 클립보드 공유는 지원하지 않습니다.

## 업그레이드

v1.0/v1.1의 1:1 설정은 기존 상대의 인증키를 유지하여 자동 변환합니다. 양쪽 모두 업데이트하면 기존 방향으로 계속 사용할 수 있습니다. 여러 대 공유에는 모든 기기가 v1.2 이상이어야 합니다. 이전 클라이언트와의 직접 1:1 통신은 유지하지만 다른 출처를 중계하는 항목은 이전 클라이언트에 보내지 않습니다.

기존에 Main이 허브였다면 newserver에서 역할을 ‘허브’로 바꾸고 저장한 뒤 Main과 Mac을 새 코드로 연결하세요. 역할 변경이나 전체 초기화 후에는 이전 코드로 연결할 수 없습니다. Windows는 기존 앱을 트레이에서 종료하고 새 EXE를 실행하세요. 자동 시작이 켜져 있으면 새 실행 경로를 갱신합니다. Mac은 앱을 응용 프로그램 폴더에 둔 뒤 자동 시작을 저장하세요.

v1.2.1은 예전 ‘매번 확인’ 설정을 처음 실행할 때 자동 수신으로 전환합니다. 명시적인 파일 차단과 파일 공유 끄기는 유지합니다. 업데이트 이후 사용자가 수동 확인을 선택했다면 다음 실행에서 다시 바꾸지 않습니다. 수신 설정이므로 newserver·다른 PC에도 각각 적용해야 합니다. 재페어링은 필요 없습니다.

## v1.2.1 검증 기록

Windows 70개, macOS 15 Apple 칩·Intel 각각 64개 검사가 통과했습니다. 허브 + 참여 컴퓨터 3대의 실제 TLS 파일 전달에서 승인 콜백을 모두 거부하도록 해도 파일이 정상 수신되고 승인 요청 자체가 발생하지 않음을 확인했습니다. 예전 확인 모드의 일회성 자동 전환, 차단·파일 끄기 유지, 이후 수동 확인 선택 보존을 검사했습니다. Windows EXE는 새 설정과 예전 설정 양쪽의 자동 수신 전환·시작·종료 검사가 통과했고 Mac 두 .app의 빌드·시작·종료도 통과했습니다. [검증 기록](../artifacts/verification-v1.2.1.json) · [Mac 빌드 기록](https://github.com/yhc1001/ClipBridge/actions/runs/39536082039).

## v1.2.0 검증 기록

v1.2의 결과는 [검증 기록](../artifacts/verification-v1.2.0.json)에 기록합니다. 자동 네트워크 검사는 한 테스트 호스트 안에서 실제 TLS 소켓과 실제 파일로 허브 + 참여 컴퓨터 3대를 구성합니다.

Windows 11에서 66개 검사가 통과했고, 최종 EXE의 실제 클립보드 양방향 텍스트·이미지·HTML/RTF·파일 수신·루프 방지·종료 및 임시 파일 정리도 통과했습니다. macOS 15 Apple 칩·Intel에서는 각각 60개 검사와 .app 시작·종료가 통과했습니다. [Mac 빌드 기록](https://github.com/yhc1001/ClipBridge/actions/runs/39243272272). Mac 빌드 이후 Windows에서 합성 형식이 추가되는 경우의 수신 처리를 보완했으며 Mac 실행 코드는 변경하지 않았습니다.

- 모든 출발지의 Unicode 텍스트·이미지·HTML/RTF 전달, 원래 출처 보존, 반복 전송 없음
- 4대 동시 복사 20회 수렴, 한 참여 컴퓨터의 연결 끊김·복구 중 다른 컴퓨터 간 전달
- 실제 다중 파일·폴더 전달, 받는 기기별 거부·승인 대기·출처별 파일 허용
- 승인된 기기마다 다른 키, 사용한 초대키 재사용·출처 위조·해제한 기기의 재접속 거부
- 허브 재시작 후 승인 보존과 자동 재접속, 기존 클립보드 재전송 없음
- 기존 1:1 설정 변환, 재전송 중 임시 파일 삭제 방지 및 정리

실물 Main/newserver/Mac 동시 연결, 16대 최대 부하, PicPick·캡처 도구·브라우저·Word·Excel·탐색기·Finder·Moonlight에서의 실제 붙여넣기, 실제 재로그인 자동 시작은 이번 버전에서 미검증입니다. Windows의 네이티브 클립보드 형식 등록과 자동 시작 레지스트리, Mac의 네이티브 pasteboard·키체인·LaunchAgent 설정 검사는 별도로 수행합니다. 과거 버전 기록은 해당 버전의 검증 JSON을 참고하세요.
