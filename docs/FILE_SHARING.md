# 파일 복사·붙여넣기

연결 후 파일·폴더를 복사하면 실제 내용을 전송합니다. 수신 PC에서 **‘이 PC에서 바로 붙여넣을 수 있습니다’**가 표시되면 탐색기/Finder/파일 관리자에서 붙여넣으세요. 전송 전에 누른 붙여넣기를 자동 실행하지 않으며, 대용량은 네트워크·디스크 속도만큼 기다려야 합니다.

## v1.6.3 개선

- Windows의 `GetClipboardData`는 지연 렌더링 중 클립보드 변경 번호를 증가시킬 수 있습니다. 읽기를 마친 시점의 번호를 기록하여 같은 복사가 진행 중인 전송을 재시작하지 않도록 했습니다. [Microsoft의 변경 번호 설명](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber).
- Windows 감지는 알림 즉시 시도하고 클립보드가 사용 중이면 5ms부터 점차 늘려 재시도합니다. 새 복사/수신마다 고정 15ms 대기와 10ms 폴링을 더하지 않습니다.
- Mac/Linux 수신은 큐 알림으로 즉시 UI 루프를 깨웁니다. Mac의 변경 확인은 50ms 주기, Linux X11의 변경은 Qt 알림을 사용합니다. OS 스케줄링/잠금/렌더링 때문에 실제 적용 지연이 0ms라는 뜻은 아닙니다.
- 양쪽에서 `file_stream=1`을 협상하면 파일명·크기·구조만 먼저 검사하고, 데이터를 한 번 읽으며 전송·SHA-256을 계산합니다. 최종 해시를 별도로 보내 수신 파일별 실제 바이트 수·해시와 비교한 뒤 등록합니다. 없는/잘못된 해시, 잘못된 오프셋/길이, 제한 초과, 위험한 경로는 거부합니다. 이전 피어는 기존 사전 해시 방식으로 전송합니다.
- 한 복사를 여러 피어로 보낼 때 준비 작업을 공유합니다. 새 복사마다 새로 검사하므로 같은 경로의 수정된 파일도 전송합니다. 파일이 일시적으로 잠겼을 때 준비/읽기 시작을 최대 5회 재시도합니다. 전송 중 파일이 수정되거나 읽기 자체가 실패하면 중단되며 다시 복사해야 할 수 있습니다.
- 수신은 청크마다 파일을 다시 여는 대신 한 전송당 최대 한 개의 파일 스트림을 재사용합니다. 완료/취소/연결 종료에 닫고 미완료 임시 파일은 정리합니다.

## 동작 범위

텍스트·이미지·파일 공유는 기존과 같은 TLS 인증 채널을 사용합니다. 승인/차단, 기본 파일 16GiB·최대 1TiB, 상대방 용량 제한, 로컬 파일만 허용, UNC·심볼릭 링크·재분석 지점 차단, 경로 검증을 유지합니다. 클립보드 이력을 영구 보관하거나 파일을 실행하지 않습니다. 완료된 파일은 붙여넣기를 위해 임시 폴더에 유지하고 다음 수신 파일로 교체하거나 종료할 때 정리합니다.

새 복사는 이전 복사보다 우선합니다. 파일을 복사한 직후 다른 텍스트 등을 복사하면 이전 파일 전송은 취소됩니다. 연결이 끊긴 동안 복사한 항목은 재연결 시 자동 전송하지 않으므로 연결 후 다시 복사하세요.

Main이 중심인 그룹은 참여 PC 사이 파일을 Main을 거쳐 전달합니다. 중계는 Main에 파일이 모두 도착한 후 시작하며, 대용량을 여러 대에 전송할 때 전체 완료 시간은 각 경로의 속도에 영향을 받습니다.
