# v1.6.2 검증

## 화면 경계 대기 제거

입력 설정의 이전 기본값은 `switch_delay=250`이었고, 내장 프로필에서 `server/enableSwitchDelay=true`, `server/switchDelay=250`으로 전달했습니다. 새 기본값은 `0`이며 대기 타이머를 끕니다.

이전 통합 그룹의 기본 대기 250ms는 최초 업데이트 시 한 번 해제합니다. 수동 연결의 지연과 250 이외의 사용자 지정값, 업데이트 후 명시적으로 바꾼 선택은 유지합니다. 이전 설정으로 새 통합 그룹을 처음 구성할 때도 즉시 전환을 적용합니다.

입력 이벤트는 별도 내장 Deskflow 1.27.0 프로세스가 직접 TLS로 전달합니다. 해당 엔진은 작은 마우스 패킷의 대기를 줄이도록 TCP_NODELAY를 사용합니다. 클립보드·파일 채널과 입력 채널은 분리돼 있습니다. 하드웨어·네트워크·DPI·게임/고부하 환경 전체의 성능이 동일하다는 보장은 아닙니다.

## 현재 PC와 로컬 검사

- 사용자가 다른 PC의 Deskflow 제거 후 ClipBridge 마우스 동작을 확인했습니다. 메인의 실제 입력 서비스에서도 native connected 상태를 확인했습니다.
- 메인의 저장된 대기 250ms를 0으로 바꾸고 ClipBridge GUI를 재시작했습니다. 자체 입력 엔진이 다시 시작됐고 설정값 0이 유지되는 것을 확인했습니다. 이 작업은 사용자가 요청한 마우스 설정 적용을 위한 것으로 기존 v1.6.1 EXE를 사용했습니다.
- 입력 설정/통합 승인/프로필/UI 관련 로컬 검사 27개 통과. 사용자 클립보드나 마우스에 테스트 입력을 보내지 않았습니다.
- 실제 장비에서 0ms 변경 후 전환 시간을 계측하거나 사용자 체감을 다시 확인한 결과는 아직 없습니다.

## 분리된 환경의 검사

Linux CI에서 두 개의 전용 Xvfb 화면과 실제 내장 엔진·TLS를 사용해 이전 250ms와 제품 기본값을 각각 세 번 측정합니다. 측정에는 테스트 입력 생성·관찰 주기·프로세스 스케줄링도 포함됩니다. Windows/Mac의 실물 화면 전환 시간이나 LAN/Tailscale의 종단 지연 수치는 아닙니다.

Windows EXE/UAC MSI, Mac ARM/Intel, Linux 빌드·검사와 전환 측정은 진행 중이며 완료 후 실행 ID와 결과를 기록합니다.
