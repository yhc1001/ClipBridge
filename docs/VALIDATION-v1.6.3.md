# v1.6.3 검증

## 파일 복사 반응·누락 수정

수정 전 합성 클립보드·로컬 TLS 회귀 검사에서 지연 렌더링 후 중복 감지, 일시적인 파일 잠금 후 전송 누락, 피어별 반복 스캔, 파일 전체 두 번 읽기를 재현했습니다. 새 파일 프로토콜의 최종 해시 검사는 신규 검사입니다. 최초 검사 5개 실패 / 2개 통과 후 구현했습니다.

새 버전끼리 파일 내용은 사전 전체 읽기 없이 전송 중 검사합니다. 테스트 파일 1,280,000바이트는 수정 전 원본에서 2,560,000바이트를 읽었고 수정 후 1,280,000바이트를 읽습니다. 세 피어에 전송하는 목록 스캔은 3회에서 1회로 줄었습니다. 이것은 원본 읽기량/스캔 횟수이며 네트워크 전송 속도가 두 배라는 측정은 아닙니다.

로컬 검사는 사용자 클립보드나 마우스 입력 없이 합성 보드·임시 파일·루프백 TLS를 사용합니다. 잠금 자동 재시도, 새 복사 취소, 잘못된/누락된 최종 해시 거부와 임시 정리, 빈 파일/빈 디렉터리, 이전 파일 프로토콜 호환, 같은 경로 수정 후 양방향 24회 연속 전송, 폴링 타이머를 정지한 상태의 수신 처리를 포함합니다.

최종 로컬 선택 검사 **112개 통과**. 이 중 파일 반응 회귀 검사는 16개이며, 전송 중 파일 변경/지속적인 잠금 이후의 다음 복사, 취소된 공유 스캔의 중계 원본 보존·정리까지 포함합니다.

## 참고 측정 · 사설 루프백 TLS

같은 v1.6.3 코드에서 **구버전 호환 모드와 새 스트리밍 모드**를 비교했습니다. 실제 v1.6.2 전체와 비교한 벤치마크는 아닙니다. 암호화 연결·디스크 임시 수신·합성 적용 콜백을 사용했고 Windows 감지/클립보드 쓰기와 LAN/Tailscale 지연은 포함하지 않습니다. OS 파일 캐시/실행 순서 영향도 있습니다.

| 항목 | 호환 모드 중앙값 | 새 모드 중앙값 | 반복 |
|---|---|---|---|
| 1,000바이트 파일 | 5.32ms | 5.14ms | 각각 10회 |
| 16MiB 파일 | 309.79ms | 299.45ms | 각각 3회 |

이 환경의 시간 차이는 작았습니다. 사전 읽기를 없앴다고 전체 파일 전송 속도가 두 배가 되지는 않습니다. 원본 읽기량/대기 감소와 누락 원인 수정을 확인했으며 실제 장비의 개선 정도는 미검증입니다.

## 운영체제별 검사·빌드

런타임 소스는 `3804d10df6b3f04a00f150d485595b0100b527ee`이며 세 플랫폼 모두 동일합니다. Windows 빌드의 `053262c1acb5e1c46833ace7011b8e0029555761`은 실제 지연 렌더링 테스트의 NULL 핸들 등록 방식을 수정한 커밋이며 제품 코드는 동일합니다.

| 플랫폼 | 전체 검사 | 빌드·실행 검사 |
|---|---|---|
| Windows x64 일반 / UAC | 133개 통과 / OS별 2개 생략 | [41382286723](https://github.com/yhc1001/ClipBridge/actions/runs/41382286723) |
| macOS ARM / Intel 각각 | 120개 통과 / OS별 9개 생략 | [41382070184](https://github.com/yhc1001/ClipBridge/actions/runs/41382070184) |
| Linux X11 x64 | 122개 통과 / OS별 9개 생략 | [41382070261](https://github.com/yhc1001/ClipBridge/actions/runs/41382070261) |

Windows는 실제 `WM_RENDERFORMAT`으로 CF_HDROP을 늦게 제공하는 전용 소유자 창과 실제 감시 스레드를 사용해, 최종 변경 번호를 기록하고 추가 복사가 발생하지 않는지 확인했습니다. 모든 네이티브 클립보드 검사는 CI의 전용 환경에서 실행했습니다. 사용자 PC의 실제 클립보드에 테스트 파일이나 입력을 주입하지 않았습니다.

Windows 일반 EXE는 새/기존 설정의 실제 감시·트레이·시작/종료와 내장 엔진 검사를 통과했습니다. MSI 설치·등록 사용자 인증·제한된 Medium IL 토큰의 조회 및 쓰기/종료 거부, 사설 방화벽, SYSTEM/UIAccess/TLS, 관리자 전용 테스트 데스크톱의 실제 입력, 자식/서비스 복구, 종료 상태 보존·제거 검사도 통과했습니다. 실제 UAC 승인 창이나 별도 제한 사용자 GUI 프로세스, 물리 재부팅 검사는 아닙니다.

Mac ARM/Intel은 실제 pasteboard·Keychain·패키지 시작/종료·내장 엔진 검사, Linux는 실제 X11 클립보드·암호화 설정·패키지 시작/종료·내장 엔진 검사를 통과했습니다. Linux의 분리된 두 Xvfb 화면에서 실제 TLS 마우스·키 전달도 통과했습니다. 기존 입력 엔진의 화면 전환 회귀 측정은 이전 250ms 설정 중앙값 275.47ms / 즉시 전환 7.47ms였습니다. 파일 전송이나 물리 PC 간 지연 수치는 아닙니다.

배포 실행 파일은 해당 CI의 바이트를 보존합니다. Mac/Linux 외부 문서는 갱신하고 MSI 내부 문서는 빌드 시점 스냅샷을 유지합니다. 최종 파일 해시는 `SHA256SUMS.txt`에 기록합니다. 현재 사용자 PC의 실행 중인 프로그램이나 설치본을 교체하거나 재시작하지 않았습니다.

## 미검증

- 사용자가 겪은 실제 PC 조합에서의 재발 여부와 체감 속도
- 실제 LAN/Tailscale 종단 지연, 디스크·백신·네트워크 부하에서의 성능
- 실물 Windows/macOS/Linux 사이 탐색기/Finder·앱별 붙여넣기, PicPick·Office·Moonlight
- 최대 용량·20,000파일·16피어 한계에서의 장시간 부하
- 실제 UAC 승인 창·잠금·로그인 화면과 물리 재부팅

파일은 모두 받은 뒤 붙여넣을 수 있습니다. 전송 완료 전의 붙여넣기를 예약하거나 중계 중인 파일을 미리 공개하지 않습니다.
