## 새 통합 연결 검사

- 실제 loopback TLS에서 IP 요청 → Main 승인 한 번으로 입력 인증서와 클립보드 장치별 키를 함께 등록했습니다. 연결 거절 시 신뢰를 저장하지 않고 재승인 알림도 반복하지 않습니다.
- 같은 승인으로 실제 `NetworkEngine` 두 개를 연결했습니다. 별도 코드·두 번째 승인을 거부하도록 설정해도 Unicode 텍스트, 이미지, 실제 파일 바이트가 양방향으로 전달됩니다. 양쪽 마우스를 OFF로 둬도 클립보드는 동작했습니다.
- Main과 참여 PC 두 대에서 같은 화면 배치를 유지하고, 참여 PC가 바꾼 배치를 나머지에 반영했습니다. 동명 PC 이름은 자동 구별합니다. 이름 변경·명령 필드·떨어진 화면·공인 IP는 거부했습니다.
- 저장한 인증서로 자동 재연결, 변경된 클라이언트 키 거부, 승인 대기 중 클라이언트 종료 시 요청 취소, 인증서/서버 바인딩 서명 검사를 통과했습니다.
- 실제 Qt 테스트 창 두 개에서 IP 버튼 → 승인 대화상자 한 번 → 연결 → 양쪽 화면 카드 표시 → 텍스트 수신 → 마우스 ON/OFF 후 연결 유지를 확인했습니다. 기본 화면에 코드·역할·좌표 입력이 없고 고급 창이 분리된 것도 확인했습니다.

Qt UI 검사는 입력 엔진·트레이·사용자 클립보드를 대체하고, 통신은 실제 TLS를 사용합니다. 각 OS의 실제 클립보드 등록 검사는 별도 네이티브 검사입니다. 이 결과는 실물 PC 사이의 원격 입력·앱별 붙여넣기 검사와 구분합니다. README의 화면 이미지는 이 격리된 Qt 검사 화면입니다.

## 설치형

일반 권한 앱의 서비스 이미지 조회에 필요한 최소 `PROCESS_QUERY_LIMITED_INFORMATION` 권한을 설치 소유자에게 추가했습니다. Medium integrity와 Admin 그룹 제외 토큰으로 impersonation한 뒤 **실제 SCM·pipe·프로세스 경로 조회**가 통과했습니다. 동일한 제한 토큰의 서비스 프로세스 메모리 쓰기·강제 종료 핸들 요청은 접근 거부되었습니다. CI의 별도 제한 사용자 프로세스 시작은 테스트 환경의 window-station 제약으로 실패해, 같은 제한 토큰을 API 권한 검사에 직접 적용했습니다. 사용자 PC의 보안 정책은 변경하지 않았습니다.

MSI 설치·사용자 SID 등록, SYSTEM/활성 콘솔 세션/UIAccess 입력 프로세스, 실제 TLS와 SYSTEM/Admin 전용 desktop의 마우스·키 입력, 임의 실행 요청 거부, 자식 및 서비스 강제 종료 후 복구, shutdown용 suspend 후 설정 유지·재연결, 명시적 stop 후 재시작 시 비활성 유지, 실제 사설 방화벽 규칙과 제거를 통과했습니다. 실제 UAC 승인 창을 자동으로 누르지 않았습니다.

## 남은 실물 확인

실제 UAC 승인 창·잠금/로그인 화면·Main/newserver 실물 재부팅·RDP/빠른 사용자 전환·실물 Windows 11의 DPI/키보드 조합은 미검증입니다. 보안 주의 시퀀스 Ctrl+Alt+Del은 보장하지 않습니다.

PicPick·캡처 도구·브라우저·Word·Excel·Explorer/Finder/Linux 파일 관리자·Moonlight 실물 앱 UI도 별도 확인이 필요합니다. 512MiB 클립보드·1TiB 파일·20,000개 항목·16대 최대 부하도 미검증입니다. [기존 지원 형식/네이티브 검사 범위](VALIDATION-v1.4.md)를 참고하세요.

Mac은 Developer ID 서명·공증이 없으며 Windows 실행 파일도 개발자 코드 서명이 없습니다. Linux는 X11 전용입니다. 배포 ZIP/TAR의 문서를 갱신해도 앱·내장 엔진 바이트와 실행 권한은 유지하며, 최종 SHA-256을 별도로 제공합니다.
